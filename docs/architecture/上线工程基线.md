# AI Werewolf 上线工程基线

本文档描述系统从“本地可运行”进入“可上线服务”所必须满足的工程条件。单局对局成功不等于生产可用。

## 当前已经完成

- 对局由 REST 创建、准备、启动，Match Worker 异步消费，不再让 HTTP 请求持有整局对局。
- 对局快照、事件、决策、检查点写入数据库，SSE 只消费持久化投影。
- Worker 使用租约、心跳、检查点和过期回收，支持异常退出后的有限重试。
- 模型请求、动作校验、领域状态机和持久化边界分层。
- SSE 在完成和失败时均发送终止事件；健康检查区分存活和数据库就绪。
- 生产配置拒绝 SQLite、fake 模型、fallback 和未配置认证。
- 生产认证支持最小可用的静态 Bearer token：
  `AUTH_TOKENS=token|actor_id|role1;role2,token2|actor2|viewer`。
  `moderator` 角色才能读取私有快照、主持人视图和 `moderator=true` 的 SSE。

## 当前不能宣称完成的事项

1. **数据库迁移**：当前仍由 `create_all` 和兼容性补丁初始化，尚未由 Alembic 统一管理。正式发布前必须引入版本化迁移、回滚脚本和迁移演练。
2. **认证升级**：静态 token 适合内部首个部署，不适合多租户公网产品。正式公网版本应替换为 OIDC/JWT，并将用户、房间和角色授权落库。
3. **TLS 和密钥管理**：Compose 不负责证书、密钥轮换和 Secret Manager。生产需要在云负载均衡或 Nginx 前配置 HTTPS，并从 Secret Manager 注入密钥。
4. **可观测性**：还需要统一 request id、match id、结构化日志、指标、trace、告警和审计留存。
5. **容量验收**：尚未完成 3000 QPM 的压测。必须分别测 REST、SSE 长连接、数据库连接池、Redis 通知和模型并发，并记录 P95/P99。
6. **高可用数据库**：必须配置 PostgreSQL 备份、恢复演练、连接池上限、磁盘告警和故障切换策略。

## 发布顺序

1. 先在独立环境运行迁移，并执行完整测试、可见性测试和真实模型小样本对局。
2. 使用 `APP_ENV=production`、PostgreSQL、真实模型、`AIWEREWOLF_STRICT_MODE=true`、`ALLOW_FALLBACK=false` 和非空 `AUTH_TOKENS` 启动 API 与 Worker。
3. 只暴露反向代理端口，PostgreSQL 和 Redis 保持内网或本机绑定，不直接暴露公网。
4. 检查 `/api/v1/health/live` 和 `/api/v1/health/ready`，确认 ready 包含数据库可用。
5. 创建一局 AI 对局，验证 REST 返回、SSE 顺序、终局事件、失败事件、数据库记录和 Worker 重启恢复。
6. 通过灰度流量和可回滚镜像发布；禁止直接在正式库执行未审计的 `create_all` 变更。

## 本地 Compose 的边界

`make deploy` 只用于本地或集成环境。它不是生产发布命令；`make deploy-down` 不再删除数据库卷。生产应使用独立的编排清单、Secret、TLS、迁移 Job 和备份策略。

## 验收门槛

- [ ] Alembic 迁移和回滚演练通过
- [ ] OIDC/JWT 或等价的正式身份系统接入
- [ ] 私有视图和房间级授权测试通过
- [ ] TLS、密钥轮换、备份恢复和告警已验证
- [ ] 3000 QPM 压测达到目标，P95/P99 有记录
- [ ] Worker、PostgreSQL、Redis 故障演练通过
- [ ] 灰度发布和回滚演练通过

在上述清单完成前，系统可以称为“工程化集成环境”，不能称为“已达到正式生产标准”。
