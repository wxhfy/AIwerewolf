# 模型无关的 Agent 设计

## 目标

AI Werewolf 的核心不是绑定某一个模型，而是让任意满足基础文本生成能力的模型，都能够在同一套规则和信息约束下参与对局。

模型可以改变角色的判断质量和表达风格，但不能改变以下事实：

- 角色能看到什么由领域层和 PlayerView 决定。
- 合法动作由游戏引擎生成。
- 角色记忆由 Harness 维护。
- 模型只能提出动作，不能直接修改游戏状态。
- 模型失败不能破坏事件流和对局状态。

## 分层边界

### 领域层

领域层只处理确定性事实：阶段、身份、存活状态、合法动作、结算和公开事件。它不依赖具体模型，也不读取模型提示词。

### Harness 层

Harness 负责把一个角色的可见状态组织成一次 DecisionRequest：

1. 接收角色安全的 PlayerView。
2. 增量更新 ActorMemory。
3. 构建公开事实、私有事实、阶段摘要和主观判断。
4. 按动作类型控制上下文预算。
5. 调用模型适配器。
6. 解析结构化结果并执行动作校验。
7. 失败时进行一次低成本修复或安全降级。

Harness 不应该知道模型是 GLM、Qwen、DeepSeek 还是本地模型。

### 模型适配层

模型适配器提供统一的 completion contract：

- 输入：标准消息列表和可选能力参数。
- 输出：标准 Chat Completion 字典。
- 能力：通过 supports_tool_calling 显式声明，不通过模型名称猜测。

当前代码仍兼容旧的 chat_sync 客户端，新的客户端可以实现 complete 方法。兼容逻辑只存在于 backend.agent_harness.model，Planner 不再直接依赖具体厂商方法。

### 输出协议

所有模型都可以使用两种方式返回动作：

1. 纯 JSON 文本：option_id、response、reasoning。
2. 标准工具调用：submit_action。

两种方式最终都转换为同一个 ActionSelection，再经过环境拥有的 ActionSpace 校验。模型不能发明目标 ID，也不能绕过响应 schema。

## 为什么不按模型写提示词

模型名称不是能力证明。同一个模型的不同部署、量化版本、API 网关和 system prompt，都可能有不同表现。通过模型名称启用工具调用会产生隐藏耦合，也会让更换模型时出现静默行为变化。

因此：

- 模型能力由适配器声明。
- 角色策略由 agent_profile 和 domain context 表达。
- 游戏规则由 ActionSpace 表达。
- 输出格式由代码校验。
- Prompt 只描述通用决策协议，不写死某个模型的特殊行为。

## 不同模型的适配策略

### 弱模型

使用纯 JSON、较短上下文、较少动作说明和确定性 fallback。目标是合法、稳定完成决策。

### 普通模型

使用完整角色状态、阶段摘要和公开声明。目标是形成连续怀疑、投票和发言。

### 强模型

可以启用工具调用、有限反思和更高上下文预算。目标是改善复杂身份博弈，但不能绕过领域校验。

这三类模型使用同一套 DecisionRequest 和 ActionSelection，不需要修改游戏引擎。

## 最小验收标准

换模型时必须通过同一套测试和对局验收：

- 结构化动作解析成功率。
- 非法动作率为零。
- 信息泄漏率为零。
- 模型超时后对局仍可继续或明确进入可恢复状态。
- 角色能看到的上下文在不同模型间完全一致。
- 同一 DecisionRequest 能被不同模型消费，不改变领域事实。

## 当前实现状态

已完成：

- ModelClient 统一协议。
- complete_chat 兼容新旧模型客户端。
- 工具调用能力改为显式声明。
- Planner 不再根据模型名称自动开启工具能力。
- 纯 JSON 和工具调用共用同一个动作校验链路。

仍需继续：

- 为各模型增加独立的 provider adapter，而不是长期依赖兼容层。
- 为超时、限流、空响应建立统一的模型错误分类。
- 用相同 DecisionRequest 对 GLM、Qwen、DeepSeek 和本地模型做横向评测。
- 把安全降级策略从开发 fallback 区分为生产可恢复动作。

## 第一性原理

所有新增功能都必须回答一个问题：

> 它是否让不同模型在同一信息约束下，更稳定地产生合法、连续、可解释、接近人类的对局行为？

如果不能直接回答“是”，就不属于当前核心改造范围。


## 响应标准化

Provider Adapter 返回统一的 Chat Completion 结构后，Harness 还会经过响应标准化层：

- 将字符串、内容块数组统一为文本。
- 将字符串工具参数和已解析对象统一为 JSON 文本。
- 校验 assistant message、tool_calls 和工具函数名的结构。
- Planner 只消费标准化结果，不处理厂商返回格式差异。

这层的意义是把“模型能力差异”和“接口格式差异”分开。模型换代不应要求修改狼人杀策略或领域引擎。


## 动作契约校验

模型只能选择环境生成的 option_id。其 response 会在执行前由 Harness 校验有限 JSON Schema：

- required 和 additionalProperties
- string 的长度边界
- number 的最小值和最大值
- enum 枚举值
- array 的元素 schema 与数量边界
- nested object 的递归字段约束

因此模型能力弱或模型格式变化时，最多触发修复或安全降级，不会把未满足环境契约的数据交给领域引擎。
