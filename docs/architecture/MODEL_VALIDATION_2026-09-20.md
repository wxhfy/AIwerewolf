# 免费模型接入验证报告

验证日期：2026-09-20。

本报告记录 SiliconFlow 免费模型在当前后端中的真实调用结果。测试使用 Hermes 本机环境变量中的 Key，Key 未写入代码、日志或 Git。

## 结论

| 模型 | 适合用途 | 实测结论 |
|---|---|---|
| `tencent/Hunyuan-MT-7B` | 翻译、多语言文本处理 | 可用。中译英约 1.01 秒，语义准确，不应承担角色策略决策。 |
| `PaddlePaddle/PaddleOCR-VL-1.5` | 图片和文档 OCR | 接口可用，约 10.45 秒；测试图中识别出中文主体，但漏掉英文并重复文本，关键业务需要后处理和更完整评测。 |
| `XingChenAGI/Xing4.0-29B` | 对话、Agent、工具调用 | 工具调用可产生合法结构化动作；普通文本 JSON 模式质量差。免费端存在明显 HTTP 500 和长尾时延，必须配置 deadline、降级和可观测性。 |

## Xing 对局结果

### 文本 JSON 模式

3 天、7 人真实模型对局完整结束：

- 总耗时：393.21 秒。
- 决策数：44。
- 修复调用：20。
- 降级动作：43。
- 平均成功请求时延：约 12.2 秒。
- P95：约 24.2 秒。
- Harness 事件：367 条。

该模式虽然不会再让状态机崩溃，但模型经常不遵守 JSON 契约，不应作为 Xing 的正式接入方式。

### 工具调用模式

1 天、7 人真实模型对局完整结束：

- 总耗时：44.90 秒。
- 决策数：5。
- 修复调用：0。
- 成功工具调用时延：1.966 秒。
- 降级动作：4，原因均为 SiliconFlow 返回 HTTP 500，不是动作解析或规则校验失败。
- Harness 事件：45 条。

工具调用显著改善结构化输出，但免费端稳定性仍不足。当前代码对 Xing 自动启用 `submit_action` 工具，也允许通过 `tool_calling` 配置显式开关。

## 当前工程策略

1. Agent 主模型优先使用原生工具调用，模型只提交服务端合法 `option_id`。
2. 普通决策一步，高影响决策最多增加一步反思。
3. 非法输出最多执行一次紧凑修复。
4. 超时、HTTP 5xx 或修复失败时，不终止整局；根据角色主观信念和关系选择合法兜底动作。
5. 所有修复、降级和错误原因写入 `agent_harness_events`，便于按模型统计稳定性。
6. Hunyuan-MT 和 PaddleOCR-VL 作为旁路能力使用，不进入狼人杀角色决策主链路。

## 上线建议

- 免费 Xing 端适合开发和链路验证，不适合直接作为正式比赛唯一模型源。
- 正式环境应为同一能力配置稳定供应商，并对 HTTP 5xx 使用受总 deadline 约束的有限重试和熔断。
- 模型质量评估必须分开统计：有效模型决策率、修复率、降级率、时延和游戏策略得分，不能只看对局是否结束。
- OCR 在进入业务前需要包含中文、英文、数字、低清晰度和复杂版面的离线评测集。
