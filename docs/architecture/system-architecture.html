Agent Harness 的一轮决策

Harness 是角色运行时，不是规则引擎，也不是数据库代理。它接收角色安全视角，输出候选动作。

1. PlayerView当前玩家能看到的公开信息、私有信息、阶段、存活列表。输入
2. ActorMemory确认事实、公开摘要、最近发言、社会判断、目标和回忆。增量
3. Context Budget按动作类型限制上下文；超预算时完整移除低优先级项。裁剪
4. Planner生成结构化 DecisionRequest，明确目标、动作空间和输出格式。组织
5. Model Adapter调用 GLM / SiliconFlow 等模型，设置超时、重试和低成本修复。外部
6. Validator解析 JSON、检查动作合法性；失败时修复或安全降级。边界

上下文组织

私有认知

自己的身份、狼人队友、预言家查验、守护结果等，只进入对应角色。

公开事实

发言、投票、死亡、警徽、阶段结果，按可见性共享。

阶段摘要

按 day + phase 增量聚合，减少重复原始事件，不替代事实事件。

主观判断

怀疑、信任、目标和注意力，是角色内部状态，不直接写回规则。

↓
规则事实由领域引擎决定；Agent 只能在授权视角内推理，并通过合法动作影响游戏。

数据持久化边界

PostgreSQL 是可恢复事实源，Redis 只做协调、通知和短缓存，不能作为唯一状态副本。

进程、线程、协程

API 进程REST、查询、SSE；协程等待 I/O，不执行整局。I/O
Match Worker 进程一个 worker 任务持有一个对局租约；模型调用是可等待的异步 I/O。执行
Analysis Worker 进程消费 Outbox 分析任务，和在线对局资源隔离。异步
线程池只隔离同步 SDK、CPU 密集解析或阻塞库，不绕过状态一致性。受控
Kubernetes生产环境按 API、Match、Analysis 分别扩缩容；数据库和 Redis 独立管理。部署

三方协作与代码边界

Frontend Owner页面展示、REST/SSE 客户端、断线重连、事件排序、用户反馈。不得实现规则或拼接 Agent 上下文。展示层
Backend / PlatformAPI、生命周期、幂等、调度、SSE、数据库、Outbox、观测。管理层
Agent / EvaluationPlayerView、角色记忆、Harness、模型适配、输出校验、策略评测和 Track B/C。智能层
三方独立开发、各自提交和合并；跨边界只通过 REST、SSE、DecisionRequest、事件 schema 和数据库契约集成。
