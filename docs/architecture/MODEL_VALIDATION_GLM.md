# GLM 官方与托管模型链路验证

> 本文同时记录 SiliconFlow 托管的 `THUDM/GLM-4-9B-0414` 与智谱 BigModel 官方免费模型 `glm-4-flash-250414` 的真实整局验证。智谱官方 Chat Completions 地址为 `https://open.bigmodel.cn/api/paas/v4/chat/completions`。项目配置 API Root `https://open.bigmodel.cn/api/paas/v4`，客户端自动追加 `/chat/completions`。

## 验证结论

本地执行环境已使用 SiliconFlow 的免费模型 `THUDM/GLM-4-9B-0414` 完成两层验证：

1. 单请求连通性验证成功，返回预期标记，耗时 4.551 秒。
2. 7 人纯 AI 整局验证成功，游戏正常进入 `GAME_END`。

|---|---:|

这次结果证明整局不是依靠兜底逻辑“假跑通”：46 次决策均由真实模型成功完成，数据库中保留了完整决策和 Harness 事件。

另执行了一次 `agentic` 模式真实请求：GLM 正确接受包含 `submit_action`、Skill 加载和角色视角工具的 `auto` 工具协议，并直接选择 `vote:P2`。本次没有调用额外工具，说明模型可以在证据充分时直接结束，而不是机械消耗工具预算。

## 如何复现

Provider 工厂已支持以下等价名称：

```text
siliconflow
silicon_flow
```

智谱官方 Provider 使用 `bigmodel`、`zhipu` 或 `glm`，读取 `BIGMODEL_API_KEY`、`ZHIPU_API_KEY` 或本机既有的 `GLM_API_KEY`。两类 Provider 不共享密钥和模型名称。

智谱官方推荐配置：

```powershell
$env:LLM_PROVIDER = "bigmodel"
$env:BIGMODEL_BASE_URL = "https://open.bigmodel.cn/api/paas/v4"
$env:BIGMODEL_MODEL = "glm-4-flash-250414"
$env:BIGMODEL_API_KEY = "<local-secret>"
python -m backend.run_demo --seed 21 --provider bigmodel
```

## 结果解释

- 当前主流程、信息隔离、结构化动作、持久化和终局推进已经能够在真实模型下工作。
- 当前性能瓶颈主要是模型等待时间以及不能并行的顺序发言，不是 Python 状态机本身。
- 单局约 216 秒不等于系统吞吐只能串行处理一局。生产吞吐由 Match Worker 数量、模型并发和数据库容量共同决定。
- 这次验证只证明可执行性和基础稳定性，不等于发言质量、推理质量和策略演进已经达到研究级标准。

## 2026-09-21 干净上下文 V1 对比验证

本轮使用智谱官方 `glm-4-flash-250414`，对 `werewolf.decision_context.v1`、角色确定性策略和公开发言审计进行了真实整局验证。对比局均为 7 人局，但模型输出具有随机性，且旧局与新局的角色分配不同，因此以下结果用于判断改动方向，不能替代多 seed A/B 实验。

| 指标 | 旧上下文基线 | 干净上下文 V1 | 变化 |
|---|---:|---:|---:|
| 对局 ID | `8b560640-db91-47f2-bdb5-64fe3dc4f9b6` | `79d80d4a-6af6-4943-b383-4132cf85621c` | - |
| 决策数 | 26 | 28 | 不同流程长度 |
| 平均输入 tokens/决策 | 6542.7 | 2874.5 | `-56.1%` |
| 平均模型时延 | 7783.7 ms | 5844.2 ms | `-24.9%` |
| 公开发言数 | 11 | 11 | 相同 |
| 发言安全重写 | 6 | 1 | `-83.3%` |
| 角色能力错配重写 | 4 | 0 | 模型原始输出减少 |
| 重复发言实例 | 4 | 0 | 消除 |
| JSON/选项修复调用 | 1 | 3 | 仍需继续优化 |
| 确定性策略覆盖 | 0 | 1 | 阻止狼人投已知队友 |
| fallback | 0 | 0 | 保持稳定 |

本轮证明的改进：

1. 去掉整份观察、整份记忆、证据图和重复策略快照后，模型输入体积明显下降，时延同步下降。
2. 上下文明确区分“确认私有事实、公共事件、他人声明、主观推断”后，重复模板发言和角色能力混淆显著减少。
3. 角色确定性策略在真实轨迹中生效，阻止了一次狼人公开投票给已知狼队友的错误动作。另一次 10 人验证局中，策略成功将被刀女巫的错误选择改为自救。

仍然存在的问题：

1. 模型仍会产生浅层或自相矛盾的推理，例如村民声称“制造混乱符合村民目标”，以及好人不信任公开报出查杀的预言家。
2. 本轮真实输出出现猎人声称自己“守了”玩家、女巫公开未使用解药等表述。验证后已补充回归规则，相关精确坏例由单元测试覆盖；这两项补丁尚未单独再跑完整真实对局。
3. 修复调用从 1 次增加到 3 次，说明结构化输出约束仍可继续收紧，不能只用 token 和发言重写率判断整体质量。
4. 单局结果仍为狼人胜，不能据此判断阵营平衡或达到人类玩家水平。下一阶段应固定配置，至少运行多个 seed，并用策略一致性、证据引用、身份能力正确率和阵营收益组成质量评分。

## 2026-09-22 上下文与策略自由度复测

本轮继续使用智谱官方 `glm-4-flash-250414`，真实对局验证了前两项调整；第三项 `game_contract` 已接入代码并由静态测试覆盖：

1. 公开发言审计改为“硬违规阻断 + 软风险记录”。角色声明、假查验、假守护、假用药、站边变化和误判都保留给对局，不再自动替换成模板句。
2. `decision_context.v1` 增加 `decision_frame`，按发言、投票、夜间行动提供目标、证据组织方式和策略自由度，但不替模型选择目标。
3. 增加公开 `game_contract`，传入本局玩家数、角色配置和声明语义。角色配置只说明角色种类与数量，不泄露个人身份，用于减少规则外角色幻觉。

结果表明，保留策略自由度后，模型没有再触发模板化重写，且模型输出可以自然地产生角色声明、怀疑、保留态度和策略性误导。代价是输入上下文增加约 14%，但平均时延下降约 7.8%，说明网络和模型采样波动仍然大于上下文长度本身。

当前仍需继续解决：模型会把不存在的身份或个人背景写进发言，`game_contract` 已提供规则词表但还需要在多 seed 测试中验证是否降低此类幻觉；这类问题应优先通过上下文和事实来源设计处理，不应继续增加逐句禁词规则。
